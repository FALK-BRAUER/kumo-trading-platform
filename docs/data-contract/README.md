# docs/data-contract

The market-data contract: what each consumer needs, what each venue can guarantee, and how the two
are matched without any venue name above the connector.

- `DESIGN.md` — the shape. Four types (Need/Offer/Binding/Reading) and the three rules that keep the
  conditionals out of the app.
- `PLAN.md` — the measured problem, the step order, and what is deliberately out of scope.

Goes here: design and sequencing for #618 and its children. Not here: per-defect writeups (those are
GH tickets) or instance configuration (that lives in `kumo-trading-platform/instances`).
